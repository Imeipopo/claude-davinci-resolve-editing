# 第 22 章　跳剪：自動剪掉說話的停頓

> 範例：[examples/22_jumpcut.py](../../examples/22_jumpcut.py)（ResolvePython 執行；分析只用 ffmpeg）
> 測試素材：`examples/make_media.sh` 產生的 `media/talk_src.mp4`、`talk_src.srt`

驗證環境：macOS 27.0.1／Resolve Studio 21.1.0.14／ffmpeg 8.1.2／2026-10-23。

口播、致詞、訪談這類「一個人對鏡頭講話」的素材，最花時間的是把句子之間的停頓一刀刀剪掉。本章把它做成：ffmpeg 找停頓 → 算出要留的區段 → 在 Resolve **新開一條時間軸**，把來源素材的各段首尾相接放上去 → 字幕跟著平移 → 輸出 → 檢查輸出。

整理自 Hao0321（[video-autopilot-kit](https://github.com/Hao0321/video-autopilot-kit) 的 `detect_long_pauses`／`build_keep_ranges`／`remap_time` 想法）。它是用 ffmpeg 直接剪檔案；本 repo 改成在 Resolve 裡組時間軸（剪輯點之後還能在 Resolve 微調），程式重寫。

### 22.1 找停頓：`silencedetect`，再往內縮一點

- 結論：`silencedetect=noise=-35dB:d=0.6` 找出 ≥ 0.6 秒的安靜段。每段兩側各留 0.15 秒（`--pad`），只剪中間；開頭與結尾的空白從第 0 格／剪到最後一格。剩下的就是要留的區段，換成格數（`round(秒 × 30)`），`endFrame` 不含（2.3）。
- 驗證：本 repo 實測（合成素材）——五句話，句間停頓實測 0.42／1.71／2.71／1.12 秒，頭 1.01 秒、尾 1.43 秒。0.6 秒以上的 5 段被剪掉；句子裡逗號的換氣（0.31～0.34 秒）和 0.42 秒的短停頓保留。664 格剩 461 格（22.1 秒 → 15.4 秒）。
- 做法：

```bash
RP="/Applications/DaVinci Resolve/DaVinci Resolve.app/Contents/Applications/ResolvePython"
"$RP" examples/22_jumpcut.py                                     # 用 make_media.sh 的測試素材並自我檢查
"$RP" examples/22_jumpcut.py talk.mp4 talk.srt --min-silence 0.8 --pad 0.2
```

- 門檻：`0.6 秒`、`0.15 秒`、`-35 dB` 是本 repo 為合成素材選的起始值，**真人口播未驗證**。底噪大、有呼吸聲的錄音要調 `--noise`；想保留更多語氣就加大 `--min-silence`。
- 不要：對「已經混了背景音樂」的音軌找停頓——音樂把停頓填滿了，什麼都找不到。對乾的人聲軌找，或先用 21.3 的人聲分離。
- 注意 macOS `say`：它每句前後自帶約 0.2 秒靜音。測試素材原本寫 0.4 秒停頓，實測是 0.62 秒，被剪掉了；改成 0.2 秒（實測 0.42 秒）才留下。**停頓長度以量到的為準，不要以「寫進去的」為準。**

### 22.2 組新時間軸：一段一個 `clipInfo`，絕對 `recordFrame`

- 結論：每個保留區段一個字典 `{"mediaPoolItem", "startFrame", "endFrame", "recordFrame": tl.GetStartFrame() + 已放長度}`。**不寫 `mediaType`**，影像和它的聲音會一起放上去、彼此連結。時間軸名稱自動往後編號（`..._v1`、`_v2`），不覆蓋舊版；放完先存專案再輸出。
- 驗證：實測通過——讀回 V1 每個片段的（起點、長度、來源起點）與計畫完全相同：`(0, 186, 26)`、`(186, 93, 254)`、`(279, 105, 420)`、`(384, 77, 550)`；A1 也是同樣四段，`GetLinkedItems()` 讀回每段影像連著同長度的那段聲音。
- 做法：見範例的主迴圈。

```python
mp.AppendToTimeline([{"mediaPoolItem": item, "startFrame": s, "endFrame": e, "recordFrame": start + pos}])
```

- 不要：沿用 `common.append()`——它固定帶 `mediaType`，只會放影像或只放聲音。

### 22.3 字幕跟著剪：同一組區段重新對時

- 結論：原始 .srt 的每個時間 t，換算成「t 之前保留了多少格」。落在被剪掉區間裡的時間，對到剪接點（前一段的尾＝下一段的頭）。換算後短於一格的句子丟掉。輸出一份新的 .srt（與輸出影片同名），再照 19.4 放上字幕軌或燒進畫面。
- 驗證：實測通過——新 .srt 配跳剪輸出，19.15 的 `caption_qa.py --asr 5` 五句全部聽到（1.00）；同一份原始 .srt 不對時直接配，最後兩句超出片長、抽聽 0.00～0.77，FAIL。

### 22.4 檢查輸出：長度、每段頭尾那一格、還有沒有停頓

- 結論：範例輸出後自己檢查三件事，全部看輸出檔：
  1. 輸出影格數＝保留格數總和（±1）：461＝461。
  2. 每一段的第一格與最後一格，是不是來源的那一格。測試素材的畫面上方用 11 個方塊畫出自己的格數（二進位），直接讀回來比：8 格全對。用自己的素材時，改成和來源同一格比像素差異（`Frame.diff` < 3）。
  3. 輸出裡不再有 ≥ `--min-silence` 的停頓。
- 驗證：實測通過（上面數字）。另外用 18.7 的 `delivery_qa.py` 檢查：黑畫面、黑邊、死空檔、影音長度（差 0.079 秒）全 PASS，響度 -16.6 LUFS（WARN，測試語音本來就小聲）。
- 做法：ffmpeg `-ss t` 會取「t 之後的第一格」，要讀第 k 格時，對準 `(k - 0.1) / fps`，不要對準 `k / fps`。

### 22.5 雷：同一個檔名重做素材

- 結論：重做 `talk_src.mp4`（檔名不變，長度從 670 格變 664 格）後直接跑，媒體池裡的舊片段還寫著 670 格，輸出在 28% 失敗（`JobStatus: Failed`）——和 20.6 同一個雷。範例現在會先比對媒體池片段的格數和 ffprobe 量到的格數，不一致就停下來、說明要刪掉舊片段。
- 驗證：實測（2026-10-23）。**照 20.6 刪掉舊片段和用到它的時間軸、從同一個路徑重新匯入後，輸出成功，但聲音在 3.37 秒之後全部消失**（畫面正常）。是 22.4 第 3 項「還有沒有停頓」抓到的（3.37～15.40 秒整段無聲）；`delivery_qa.py` 的「長時間無聲」也會 WARN。同一個檔案複製到新路徑再跑，一切正常。只遇過一次，原因未查。
- 做法：素材改版就**換檔名**（`talk_v2.mp4`），不要覆蓋同名檔。

### 22.6 還沒做、沒測的

- 真人口播素材（底噪、呼吸、口水音）未測；門檻要自己量。
- 剪接點聲音有沒有「啪」一聲：本例都剪在靜音裡，沒有出現；`--pad 0` 剪在聲音上的情況未測。可以在每段加極短的音訊淡入淡出（未測）。
- 來源影格率必須和時間軸一樣（30 fps），否則範例直接停止；轉檔另做。
- 「嗯、啊」這類填充詞：音量不低，`silencedetect` 抓不到，要靠語音辨識的字級時間，未做。

> 人類補充：自動跳剪很快，但剪得太乾淨會像機器人。先用預設值剪一版給人看，覺得太趕就把 `--min-silence` 加大、`--pad` 加長，再開一條新時間軸重剪——舊版還在，可以對照。
